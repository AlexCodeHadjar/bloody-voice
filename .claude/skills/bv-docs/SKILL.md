# Документы — только Markdown

Все документы и заметки проекта — `.md` в `docs/`. Word (`.docx`) не создаём, не читаем и не правим
(решение владельца): если просят «ворд» или «документ» — делаем `.md` и говорим об этом.

| Что | Где | Как менять |
|---|---|---|
| Дизайн-документ (GDD) | `docs/gdd/*.md`, оглавление `docs/gdd/README.md` | правь файлы разделов напрямую; новый раздел — новый файл + строка в README |
| Промты: модули, твари, иконки | `docs/art-prompts/*.md` | **генерируются** из данных — правь `data/gear`, `data/monsters`, `data/ui/icons.json`, затем `python tools/gen_art_prompts.py` |
| Шаблоны для промтов | `docs/assets/templates/` | `python tools/gen_art_templates.py` |
| Схема города | `docs/assets/map/` | `python tools/gen_city_sketch.py` |
| Решения, заметки, планы | `docs/notes/<тема>.md` | короткие файлы по теме, с датой в начале |

## Как писать

- Разделы GDD — один файл на раздел, чтобы читать только нужное. Заголовки `#`/`##`, таблицы, списки.
- Картинки — относительными ссылками (`![...](../assets/map/city_sketch.png)`), их видно на GitHub.
- Изменил механику в коде → поправь соответствующий раздел `docs/gdd/`, чтобы документ не врал.
- После правки GDD, которая меняет механику, контент или экран, — `design-critic` (цикл из CLAUDE.md).
